OBSERVED FAULTS

Recovery's persisted detach can survive a driver disable/enable cycle.

CHANGES
- Narrow1167 fallback through SetupAPI DIF_PROPERTYCHANGE. Enable uses global
  then current-profile scope; disable uses current-profile scope, following
  Microsoft's DevCon pattern. Only exact owned devices with verified binding
  and eligible native state may enter the fallback. It requires administrator
  approval and preserves Windows restart flags. No driver package or signing
  policy changed. No device was recreated or unrelated driver modified.
- Successful state operations must reach native0/enabled or22/disabled within
  a bounded wait. Utility success alone is insufficient. Disabled-state handling
  also covers pair-upgrade cleanup and disconnect races.
- Separate enumeration of inactive adapters. Preparation matches exact current
  owned keys, checks advertised nonzero modes, and attaches only missing owned
  outputs nonprimary beside an existing display. Missing/ambiguous identities
  are never guessed; normal monitor detection remains attached-only.
- Recovery remains armed before enable or attachment. Adapter inventory is
  retained as a diagnostic sidecar; journals remain reserved for recovery.

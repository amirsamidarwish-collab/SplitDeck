SplitDeck v0.2.0 EXPERIMENTAL — 18 October 2026

STATUS
Three-screen activation and restoration passed a live Chrome + Discord trial.
User confirmed all three regions, Discord and the pointer worked.
GPU parity with two physical monitors has NOT been achieved or demonstrated.
The packaged partial-copy build completed its live retry after administrator
approval. Nominal pixel-copy volume fell 41.2% against full copies of the same
acquired frames. Whole-GPU utilization remained25.5%; the performance target
is still unmet. User confirmed Chrome and Discord were visible and usable and the pointer
responded normally; automated Chrome phases completed.

FEATURES
Two or three independent Windows displays presented on one physical panel.
Portrait / 16:9 center / portrait preset, center primary; editable screen order
and primary selection. Each screen has aspect/orientation, exact visible W/H,
exact render W/H and refresh controls. Zero dimensions mean automatic.
Invalid ratios, overlap/overflow and dimensions that cannot fit are rejected.
Narrow app regions may be smaller than an application's minimum window width.
Old two-screen profiles remain supported. Three owned devices are retained when
using two screens; the unused device stays disabled. Use v0.2.0 or newer after
three-device setup because older builds only understand two owned devices.

FIXES
Physical display group stays connected above virtual sources, preventing Windows
from rearranging the left portrait below the center. Actual positions, modes,
refresh and primary are checked before presentation; requested/actual topology
diagnostics are retained. Activation errors no longer falsely imply failed
restoration when the helper has confirmed RESTORED.
Background readiness checks preserve focused editor drafts and caret selection.
Exact render mode clears the previous render-detail preset.

GPU CHANGE — COPY VOLUME REDUCED; OVERALL TARGET UNMET
Fresh frames copy dirty rectangles and moved destination rectangles from the
current acquired image. Bounded to 64 rectangles and 60% nominal pixel coverage;
otherwise a full copy is used. Startup, resize, capture recovery, rotation,
missing/invalid/truncated metadata and invalid rectangles also use full copies.
No render resolution, virtual refresh or physical refresh reduction is enabled
by this change. No CPU readback or blocking query wait was added.
Telemetry reports submitted pixel-copy bytes, not measured hardware bus traffic.

No performance guard was loosened. Normal desktop is restored.

COMPETITORS
See docs/competitor-controls-2026-10-18.txt for pinned GitHub source links.
DesktopSplitter already offers 2–4 screens, exact per-segment dimensions and a
center-with-portrait-wings preset. MonitorSplit exposes separate refresh inputs.
Those features alone are not unique. SplitDeck's plausible distinction is the
combination of aspect locks, independent visible/render dimensions, per-screen
refresh and narrow native portrait regions. Competitors were not installed or
benchmarked; source inspection does not establish runtime reliability or speed.

LIMITS / NEXT REQUIRED CHECK
Continue investigating total GPU cost; the completed partial-copy retry reduced
copy volume but did not establish near-physical-monitor GPU overhead.
No physical dual-monitor baseline, gaming FPS/latency or long-session test.
Chrome automation used its isolated DevTools profile. Native mouse usability was
confirmed by the user, not automated. Near-zero overhead is not established.

USE
Run SplitDeck.exe from the complete v0.2.0 folder. Select count/preset, edit
dimensions, Setup driver if needed, then Apply. Restore desktop or
Ctrl+Alt+Shift+F12 ends the session. Closing the editor also restores it.
